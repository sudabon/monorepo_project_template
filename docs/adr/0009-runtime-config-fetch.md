# 0009: 環境設定は実行時に fetch する

- 状態: 採用
- 日付: 2026-09-06

## 判断

SPA の成果物は環境に依存させない。Vite の `import.meta.env` / `VITE_*` で接続先を埋め込まない。起動時に `/config.json` を 1 回取得し、zod で検証してから React を描画する。取得失敗やスキーマ不一致はエラー画面にし、既定値では動かさない。

`apiBaseUrl` と `authBaseUrl` は両方必須。配信時は `config.json` を `Cache-Control: no-cache` にする。手順は [docs/web.md](../web.md)。

## 理由

環境ごとにビルドし直すと、案件が増えるほど「どの成果物がどの環境か」を追えなくなる。同じ成果物を配り、接続先だけ差し替える方が運用が単純になる。既定値で動かすと、誤った API に書き込む事故になる。

## 代替案

| 案 | 結果 |
| --- | --- |
| `VITE_*` をビルド時に埋め込む | 環境の数だけ成果物が増える。差し替えに再ビルドが要る。却下 |
| 取得失敗時にハードコードした URL で動かす | 誤接続先で書き込み得る。却下 |
| HTML にインラインで設定を書く | キャッシュと CSP の扱いが `index.html` と結びつく。独立した `config.json` の方が差し替え単位が小さい |

参考: Phase 4 `design.md` D1、[docs/web.md](../web.md)。
