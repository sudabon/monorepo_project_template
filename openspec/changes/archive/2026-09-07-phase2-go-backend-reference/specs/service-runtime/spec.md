## Purpose

Go サービスをコンテナオーケストレータ上で安全に運用するための実行時の振る舞いを定める。ヘルスチェックの粒度、停止時のリクエスト保護、障害時に追跡可能なログ出力を含む。

## ADDED Requirements

### Requirement: ヘルスチェックの粒度分離

サービスは 2 種類のヘルスチェックエンドポイントを提供しなければならない (MUST)。shallow check はプロセスが応答可能であることのみを判定し、外部依存を参照してはならない (MUST NOT)。deep check は依存先（データベース等）の生死を判定に含めなければならない (MUST)。

#### Scenario: 依存先が停止していても shallow は成功する

- **WHEN** データベースを停止した状態で shallow check を呼び出す
- **THEN** 正常を示す応答が返る

#### Scenario: 依存先が停止していると deep は失敗する

- **WHEN** データベースを停止した状態で deep check を呼び出す
- **THEN** 異常を示す応答が返り、どの依存先が異常かが応答に含まれる

#### Scenario: すべて正常な場合

- **WHEN** 依存先が正常な状態で shallow check と deep check を呼び出す
- **THEN** いずれも正常を示す応答が返る

### Requirement: Graceful shutdown

サービスは SIGTERM を受信したあと、処理中のリクエストを完了させてから終了しなければならない (MUST)。SIGTERM 受信後に新規リクエストを受け付けることは要求しない。完了を待つ時間には上限を設け、上限を超えた場合は強制終了しなければならない (MUST)。

#### Scenario: 処理中のリクエストが完了する

- **WHEN** 応答に時間がかかるリクエストの処理中に SIGTERM を送出する
- **THEN** そのリクエストは中断されずに応答を返し、その後にプロセスが終了する

#### Scenario: 待機上限を超えた場合

- **WHEN** 待機上限を超えても完了しないリクエストがある状態で SIGTERM を送出する
- **THEN** 上限到達後にプロセスが終了し、終了したことがログに記録される

### Requirement: 構造化ログとリクエスト ID の伝播

サービスはログを構造化形式で出力しなければならない (MUST)。各リクエストにはリクエスト ID を割り当てなければならない (MUST)。クライアントがリクエスト ID を送ってきた場合はそれを引き継ぎ、ない場合は新たに生成しなければならない (MUST)。同一リクエストの処理中に出力されるログには、同じリクエスト ID が含まれなければならない (MUST)。

#### Scenario: リクエスト ID の生成

- **WHEN** リクエスト ID を含まないリクエストを送る
- **THEN** サービスがリクエスト ID を生成し、応答と、そのリクエストに関するすべてのログに同じ ID が含まれる

#### Scenario: リクエスト ID の引き継ぎ

- **WHEN** リクエスト ID を含むリクエストを送る
- **THEN** そのリクエストに関するログと応答に、送った ID と同じ値が含まれる

#### Scenario: エラー時の追跡

- **WHEN** サーバ内部エラーが発生するリクエストを送る
- **THEN** エラーログにリクエスト ID が含まれ、応答からも同じ ID を得られる
