## Purpose

ブラウザからの認証を BFF に閉じ込め、SPA にトークンを渡さない構造を提供する。セッションの発行・確認・失効、CSRF 保護、backend への認証済みコンテキストの受け渡しを定める。

## ADDED Requirements

### Requirement: Cookie セッションによる認証

BFF は、正しい資格情報によるログインに対してセッションを発行し、httpOnly かつ Secure かつ SameSite=Lax の Cookie として設定しなければならない (MUST)。認証トークンやセッション識別子を、レスポンスボディやスクリプトから読める形でクライアントに渡してはならない (MUST NOT)。

#### Scenario: ログインでセッションが発行される

- **WHEN** 正しい資格情報でログインする
- **THEN** セッション Cookie が設定され、その Cookie に httpOnly / Secure / SameSite=Lax の属性が付与されている

#### Scenario: 資格情報が誤っている場合

- **WHEN** 誤った資格情報でログインする
- **THEN** 認証失敗の応答が返り、セッション Cookie は設定されない

#### Scenario: トークンをクライアントに渡さない

- **WHEN** ログインに成功した応答の本文とヘッダ(Cookie を除く)を確認する
- **THEN** 認証トークンやセッション識別子に相当する値が含まれていない

### Requirement: セッション状態の確認

BFF は、現在のセッション状態を確認するエンドポイントを提供しなければならない (MUST)。認証済みの場合は、SPA が表示に必要とする範囲のユーザ情報を返さなければならない (MUST)。未認証の場合は認証されていないことを示さなければならない (MUST)。

#### Scenario: 認証済みでの確認

- **WHEN** 有効なセッション Cookie を伴ってセッション確認を呼び出す
- **THEN** 認証済みであることと、表示に必要な範囲のユーザ情報が返る

#### Scenario: 未認証での確認

- **WHEN** セッション Cookie を伴わずにセッション確認を呼び出す
- **THEN** 未認証であることを示す応答が返る

### Requirement: ログアウトによるセッション失効

ログアウトはサーバ側のセッションを失効させなければならない (MUST)。Cookie の削除だけに依存してはならない (MUST NOT)。

#### Scenario: ログアウト後は保護リソースにアクセスできない

- **WHEN** ログアウトしたあと、失効前の Cookie の値を伴って保護されたリソースを要求する
- **THEN** 未認証として拒否される

### Requirement: 未認証リクエストの扱い

保護されたリソースへの未認証リクエストに対し、BFF は 401 を返さなければならない (MUST)。ログイン画面へのリダイレクトを返してはならない (MUST NOT)。

#### Scenario: 未認証で保護リソースを要求する

- **WHEN** セッション Cookie を伴わずに保護されたリソースを要求する
- **THEN** 401 が返り、リダイレクト応答ではない

#### Scenario: 無効なセッションでの要求

- **WHEN** 失効済みまたは改竄されたセッション Cookie を伴って保護されたリソースを要求する
- **THEN** 401 が返る

### Requirement: CSRF 保護

BFF は、状態を変更するリクエストに対して CSRF 保護を適用しなければならない (MUST)。有効な CSRF トークンを伴わない状態変更リクエストは拒否しなければならない (MUST)。SPA が CSRF トークンを取得する手段を提供しなければならない (MUST)。

#### Scenario: トークンなしの状態変更リクエスト

- **WHEN** 有効なセッションを持つが CSRF トークンを伴わない状態変更リクエストを送る
- **THEN** リクエストが拒否され、対象の状態は変更されない

#### Scenario: 不正なトークンでの状態変更リクエスト

- **WHEN** 有効なセッションと、そのセッションに対応しない CSRF トークンを伴うリクエストを送る
- **THEN** リクエストが拒否される

#### Scenario: 正しいトークンでの状態変更リクエスト

- **WHEN** 有効なセッションと、正しく取得した CSRF トークンを伴う状態変更リクエストを送る
- **THEN** リクエストが受理される

### Requirement: backend への認証済みコンテキストの転送

BFF は backend へ転送する際、認証済みユーザを識別する情報とリクエスト ID を付与しなければならない (MUST)。リクエスト ID は、クライアントから受け取った場合はそれを引き継ぎ、ない場合は生成しなければならない (MUST)。クライアントから送られた認証済みユーザ情報を、検証せずに backend へ転送してはならない (MUST NOT)。

#### Scenario: ユーザ情報とリクエスト ID の付与

- **WHEN** 認証済みのリクエストを BFF が backend へ転送する
- **THEN** backend が受け取るリクエストに、認証済みユーザを識別する情報とリクエスト ID が含まれる

#### Scenario: クライアントによるユーザ情報の詐称

- **WHEN** クライアントが認証済みユーザ情報に相当するヘッダを自分で付けてリクエストを送る
- **THEN** BFF はその値を破棄し、セッションから導いた値で上書きして転送する

#### Scenario: リクエスト ID の引き継ぎ

- **WHEN** クライアントがリクエスト ID を伴ってリクエストを送る
- **THEN** backend が受け取るリクエスト ID がクライアントの送った値と一致する
