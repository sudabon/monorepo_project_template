## MODIFIED Requirements

### Requirement: 層構造と依存の向き

実装は handler / usecase / domain / repository の層に分割しなければならない (MUST)。依存の向きは内側（domain）を向いていなければならず、domain から外側の層への依存があってはならない (MUST NOT)。この制約は機械的に検査できなければならない (MUST)。検査の対象は層の間の依存だけでなく、各層が利用してよい外部モジュールにも及ばなければならない (MUST)。層ごとに外部モジュールの許可リストを宣言し、宣言にない外部モジュールの利用を検出しなければならない (MUST)。

#### Scenario: 逆方向の依存が検出される

- **WHEN** domain 層から handler 層または repository 実装への依存を追加して検査を実行する
- **THEN** 検査が失敗し、違反箇所が出力される

#### Scenario: 契約の実装漏れが検出される

- **WHEN** 契約に定義された操作のうち 1 つを実装しない状態でビルドする
- **THEN** ビルドが失敗する

#### Scenario: 許可していない外部モジュールが検出される

- **WHEN** ある層に、その層の許可リストにない外部モジュールの import を追加して検査を実行する
- **THEN** 検査が失敗し、違反箇所が出力される
