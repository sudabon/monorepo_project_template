# sample-resource-ui Specification

## Purpose
サンプルリソースを DB からブラウザまで貫通させた参照実装を提供する。案件側がコピーして画面を増やすための型であり、一覧の状態保持・フォームのエラー表示・破壊的操作の確認という、画面を作るたびに必要になる振る舞いを定める。

## Requirements

### Requirement: 一覧画面の検索条件とページ位置の URL 保持

一覧画面は、検索条件とページ位置を URL に保持しなければならない (MUST)。URL を再度開いた場合、同じ検索条件とページ位置の一覧が表示されなければならない (MUST)。

#### Scenario: 検索条件がリロード後も保持される

- **WHEN** 一覧画面で検索条件を変更したあと、ブラウザをリロードする
- **THEN** 変更後の検索条件が維持された一覧が表示される

#### Scenario: ページ位置がリロード後も保持される

- **WHEN** 一覧画面で 2 ページ目へ移動したあと、ブラウザをリロードする
- **THEN** 2 ページ目の内容が表示される

#### Scenario: URL の共有

- **WHEN** 検索条件を設定した状態の URL を、同じ認証状態の別のセッションで開く
- **THEN** 同じ検索条件の一覧が表示される

### Requirement: 一覧から詳細への遷移

一覧の各項目から、その項目の詳細画面へ遷移できなければならない (MUST)。詳細画面には、その項目の内容が表示されなければならない (MUST)。

#### Scenario: 詳細の表示

- **WHEN** 一覧から任意の項目を選んで詳細画面へ遷移する
- **THEN** その項目の内容が表示される

#### Scenario: 該当データがない一覧

- **WHEN** 検索条件に合致するリソースが 1 件も存在しない状態で一覧を表示する
- **THEN** エラーではなく、該当がないことを示す表示が出る

### Requirement: 作成と編集

利用者はサンプルリソースを作成および編集できなければならない (MUST)。作成・編集が成功した場合、その結果が一覧または詳細に反映されなければならない (MUST)。サーバから返された検証エラーは、対応するフォーム項目に表示されなければならない (MUST)。

#### Scenario: 作成した内容が一覧に現れる

- **WHEN** 作成フォームから有効な内容を送信する
- **THEN** 作成が成功し、一覧にその項目が現れる

#### Scenario: 編集した内容が詳細に反映される

- **WHEN** 既存の項目を編集フォームから更新する
- **THEN** 更新が成功し、詳細画面に更新後の内容が表示される

#### Scenario: サーバ検証エラーの表示

- **WHEN** クライアント側の検証を通過するがサーバ側で拒否される内容を送信する
- **THEN** 該当するフォーム項目にサーバからのエラーが表示され、リソースは作成・更新されない

### Requirement: 確認を伴う削除

削除は、実行前に利用者へ確認を求めなければならない (MUST)。確認を取り消した場合、削除を実行してはならない (MUST NOT)。削除が成功した場合、対象は一覧から消えなければならない (MUST)。

#### Scenario: 確認して削除する

- **WHEN** 項目の削除を実行し、確認を承認する
- **THEN** 対象が削除され、一覧から消える

#### Scenario: 確認を取り消す

- **WHEN** 項目の削除を実行し、確認を取り消す
- **THEN** 対象は削除されず、一覧に残る
